# دراسات الشركات

مساحة عمل عربية خاصة لإعداد دراسات أداء الشركات المدرجة، تعتمد على مصادر مسجلة وحسابات حتمية. الواجهة تعمل على Sites/Vinext، مع D1 للسجلات وR2 للتقارير ونصوصها.

## ما يعمل

- دراستان أوليتان للحبيب والبابطين بأرقام رسمية متاحة حتى تاريخ قطع 2026-11-02، مع تمييز فجوات التحقق.
- مؤشرات نمو وهوامش ومقارنات ربع سنوية؛ القيم المفقودة لا تتحول إلى صفر.
- رفع PDF/TXT/CSV/JSON، واستخراج النص مع أرقام الصفحات من PDF النصي داخل المتصفح. الملفات الممسوحة تحتاج OCR أو قراءة بصرية منفصلة.
- حفظ الدراسات واستيراد JSON وتصدير CSV وطباعة تقرير كامل إلى PDF.
- أدوات وكيل عبر POST /mcp: list_studies, read_study, list_reports, read_report, study_workflow, save_study.
- عزل سجلات كل مستخدم باستخدام معرف ChatGPT الموثوق الذي تحقنه منصة Sites.

## طريقة العمل مع الوكيل

النموذج الذي يدير البحث هو وكيل المحادثة في ChatGPT، وليس خدمة نموذج مستقلة داخل الموقع. تُنشأ إضافة الموقع عند نشره مع capability mcp. بعد تثبيت/ربط الإضافة، يستطيع الوكيل قراءة التقارير وحفظ دراسات جديدة. رفع الملف وحده لا يطلق تحليلًا لغويًا ولا جمعًا مجدولًا من تداول. لا توجد مفاتيح نموذج مضمنة أو وعود بأعمال خلفية مستمرة.

1. ارفع التقارير وحدد الشركة والفترة.
2. اطلب من الوكيل استخدام الإضافة وإعداد دراسة مقارنة وتسجيل الأدلة.
3. ينفذ save_study فحوص البنية والمصادر والفترات ويحسب المؤشرات.
4. راجع المصادر والنواقص، ثم صدّر التقرير.

## الحسابات

الوحدة الموحدة هي مليون ريال سعودي. هامش الربح = الربح / الإيرادات ×100. النمو غير متاح عند غياب البيانات أو إذا كانت قاعدة المقارنة صفرية أو سالبة. لا تنشأ مقارنة ربعية عند غياب الربع السابق مباشرة.

اشتقاق الربع من التراكمي يسمح ببنود التدفق فقط ومع توحيد السنة والوحدات وأساس المقارنة؛ لا تطرح أرصدة النقد والديون. التقرير يخزن التراكمي المعلن منفصلًا لأن التقريب قد يغيّر مجموع الأرباع. الحقول fieldSources تسجل أي حقل مصدره مختلف عن إعلان الربع.

نسبة تغطية المراجع لا تمثل دقة الأرقام ولا اكتمال تحليل السيولة. فحوص النظام لا تتحقق تلقائيًا من صحة محتوى المصدر. يجب أن تظل الدراسات مسودات حتى المراجعة البشرية.

## التحقق

```
node --test test/study-engine.test.mjs
pnpm exec tsc --noEmit
```

مصادر العينة محفوظة في data/hmg.json وdata/albabtain.json. الربع الثالث للحبيب معلق للتحقق من الأصل، وعدم إدراج ربع لا يثبت أن الشركة لم تنشره.

## التطوير والنشر

استخدم إجراءات Sites الموجودة في المحادثة. المهاجرات في drizzle/ خاصة بالمخطط ولا تحتوي بيانات مستخدمين. الحقول DB وBUCKET اختيارية في الأنواع، لكن التطبيق يتطلب ربطهما وقت التشغيل. البيانات لا تحفظ في localStorage. معاينة التطوير تستخدم local-preview فقط عند NODE_ENV=development؛ المنشور يتطلب هوية منصة موثوقة.
